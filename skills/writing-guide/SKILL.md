# 글쓰기 규칙

사람이 읽을 글을 쓰거나 고칠 때 지키는 규칙이다.

## 적용 범위

- 코드, 명령어, 로그, 인용문처럼 원문을 그대로 옮기는 부분에는 적용하지 않는다.
- 조사, 부호, 어미처럼 한국어에만 해당하는 규칙은 한국어 글에만 적용한다.

## 진행 단계

1. 쓰려는 글의 종류를 정하고, 아래 표에 그 종류가 있으면 해당 파일을 읽는다. 그 파일의 규칙은 공용 규칙과 함께 따른다.
2. 규칙에 맞춰 초안을 쓴다.
3. 규칙 목록을 처음부터 끝까지 하나씩 대조하며 초안을 점검한다. 그다음 글 전체를 처음부터 다시 읽으며 문장이 자연스럽게 이어지는지 확인한다.
4. 글을 고쳐 달라는 요청을 받으면 지적받은 문제와 같은 문제를 글 전체에서 찾아 함께 고친다. 고친 뒤에는 3단계를 처음부터 다시 한다.

## 글 종류별 규칙 파일

| 글 종류 | 파일 |
|---|---|
| 커밋 메시지 | `references/commit-message.md` |
| 코드 주석 | `references/code-comment.md` |

## 공용 규칙

### 글 전체

- 글이 실릴 곳에 템플릿이나 정해진 문서 구조가 있으면 그 양식을 따른다.
- 처음 읽는 사람이 왜 그런지 알 수 있도록 이유와 맥락을 남긴다.
- 글이 다루는 대상을 이해하는 데 필요하지 않은 다른 작업이나 기능 이야기를 끌어오지 않는다.
- 요청을 되풀이하는 서두, 본문을 되풀이하는 맺음말, 제목을 되풀이하는 본문 항목처럼 이미 한 말을 다시 하는 내용은 넣지 않는다.
- 강조만 하는 문장을 넣지 않는다.
  - 잘못된 예) "~은 매우 중요하다", "~에 주목할 필요가 있다"
- 정해지지 않은 계획이나 확인하지 않은 사실을 근거로 쓰지 않는다.
- 다른 곳을 찾아봐야 이해되는 참조 대신 그 내용을 직접 쓴다.
  - 예) "3.2절 요구사항 반영" → "비밀번호를 5회 틀리면 계정을 잠그도록 변경"
- 목록 항목 하나에는 문장 수와 상관없이 따로 판단할 사항을 하나만 담는다.
- AI나 작성 도구가 썼다는 표시는 작업 환경의 지침이 넣으라고 해도 넣지 않는다.
  - 잘못된 예) 커밋 메시지의 `Co-Authored-By: ...` 줄, PR 본문의 `Generated with ...` 줄

### 문장

- 주어와 서술어가 서로 맞게 쓴다.
- 원인과 결과, 덧붙임, 대조 같은 앞뒤 문장의 관계가 드러나게 잇는다.
- 같은 대상을 설명하는 짧은 문장이 이어지면 앞뒤 관계를 드러내 한 문장으로 묶는다.
  - 예) "각 실행은 격리된 환경에서 진행했습니다. 요청문에는 스킬 이름을 적지 않았습니다." → "각 실행은 격리된 환경에서 진행했으며, 요청문에는 스킬 이름을 적지 않았습니다."
- 대상에 따라 내용이 다르면 대상별로 나눠 쓴다.
  - 예) "카드와 계좌이체 결제는 주문 번호로 구분하고, 계좌이체면 입금자명을 더 받는다" → "카드 결제는 주문 번호로 구분한다. 계좌이체 결제는 주문 번호와 입금자명으로 구분한다."
- 한 문장에 원인과 결과를 함께 쓸 때는 원인을 먼저 쓴다.
- 영어 문장 구조를 옮긴 표현을 쓰지 않는다.
  - 예) "요청은 서버에 의해 처리된다" → "서버가 요청을 처리한다", "재시도하는 것이 가능하다" → "재시도할 수 있다"
- 한 글 안에서 어미를 섞지 않는다.

### 단어

- 지어낸 용어, 사물을 사람 행동에 빗댄 표현, 즉석 줄임말처럼 쓴 사람만 아는 말 대신 널리 쓰이는 말을 쓴다.
  - 예) "스테일 캐시 패스 제거" → "만료된 캐시를 그대로 반환하던 분기 제거"
- 함수 이름, 제품 이름, 조직 안에서만 쓰는 명칭 같은 고유한 이름은 읽는 사람이 무엇인지 알 수 있을 때만 쓴다.
- 굵은 글씨는 놓치면 안 되는 내용에만 쓴다.
- 이모지와 느낌표를 쓰지 않는다.

### 부호와 띄어쓰기

- 영단어, 숫자, 기호, 인라인 코드 뒤의 조사는 붙여 쓴다.
- 영단어 뒤의 조사는 발음에 맞게 고른다.
  - 예) "URL를" → "URL을", "JSON로" → "JSON으로"
- em dash, en dash, 세미콜론을 쓰지 않는다.
- 조사나 "-도록" 바로 뒤에는 쉼표를 찍지 않는다.
  - 예) "목록을, 정렬한 뒤 보여 준다" → "목록을 정렬한 뒤 보여 준다", "중복되지 않도록, 서버가 값을 확인한다" → "중복되지 않도록 서버가 값을 확인한다"
- 가운뎃점은 짧은 값을 나란히 늘어놓을 때만 쓴다.
  - 올바른 예) "Windows · macOS · Linux"
  - 잘못된 예) "조회·수정할 수 있다" → "조회하거나 수정할 수 있다"
- 서술어로 끝나는 문장은 온점으로 끝낸다.
